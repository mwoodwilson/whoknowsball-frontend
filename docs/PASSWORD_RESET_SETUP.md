# Password Reset Setup Guide

This guide walks through configuring the password reset flow in Supabase for WhoKnowsBall authentication.

## Overview

The password reset flow allows users to recover their accounts by:
1. Requesting a password reset link via email
2. Clicking the link in their email (opens app via deep link)
3. Entering a new password in the app
4. Successfully logging in with the new password

---

## 1. Configure Deep Linking

The app has already been configured to handle password reset deep links.

### iOS Configuration

File: `ios/WhoKnowsBall/Info.plist`

The URL scheme `whoknowsball://` is already configured.

### Android Configuration

File: `android/app/src/main/AndroidManifest.xml`

The intent-filter for `whoknowsball://` scheme is already configured.

### React Navigation Configuration

File: `App.tsx`

Deep linking configuration includes:
```typescript
const linking = {
  prefixes: ['whoknowsball://'],
  config: {
    screens: {
      PasswordReset: 'auth/reset-password',
      // ... other screens
    },
  },
};
```

## 2. Update Supabase Email Template

You need to update the password reset email template in Supabase to use the deep link redirect URL.

### Step 1: Access Email Templates

1. Go to [Supabase Dashboard](https://app.supabase.com/)
2. Select your WhoKnowsBall project
3. Navigate to **Authentication > Email Templates**
4. Select **Reset Password** from the template list

### Step 2: Update the Template

The default template uses a web URL that won't work for mobile apps. You need to update it to use the deep link.

**Find the reset link in the template:**
```html
{{ .ConfirmationURL }}
```

**Make sure the Redirect URL in ForgotPasswordScreen matches:**

In `src/screens/Auth/ForgotPasswordScreen.tsx`, the code calls:
```typescript
await supabase.auth.resetPasswordForEmail(email, {
  redirectTo: 'whoknowsball://auth/reset-password',
});
```

This `redirectTo` parameter tells Supabase where to redirect the user after clicking the reset link.

### Step 3: Customize Email Template (Optional)

You can customize the email template to match your app's branding. Here's a recommended template:

```html
<h2>Reset Your Password</h2>

<p>Hi there,</p>

<p>We received a request to reset your password for your WhoKnowsBall account.</p>

<p>Click the button below to reset your password. This link will expire in 1 hour.</p>

<a href="{{ .ConfirmationURL }}" style="display: inline-block; padding: 12px 24px; background-color: #14B8A6; color: white; text-decoration: none; border-radius: 8px; font-weight: bold; margin: 16px 0;">
  Reset Password
</a>

<p>If you didn't request this password reset, you can safely ignore this email.</p>

<p>Thanks,<br>
The WhoKnowsBall Team</p>

<hr>
<p style="font-size: 12px; color: #666;">
  If the button doesn't work, copy and paste this link into your browser:<br>
  {{ .ConfirmationURL }}
</p>
```

**Important:** The `{{ .ConfirmationURL }}` variable is automatically generated by Supabase and includes:
- The reset token
- The redirect URL you specified (`whoknowsball://auth/reset-password`)

### Step 4: Save the Template

1. Click **Save** to save your email template changes
2. Supabase will now use this template for all password reset emails

## 3. Password Reset Flow

### User Flow

1. **Request Reset**
   - User taps "Forgot Password?" on LoginScreen
   - User enters email on ForgotPasswordScreen
   - User taps "Send Reset Link"
   - App calls `supabase.auth.resetPasswordForEmail()`
   - Success message appears: "Check your email for reset link"

2. **Receive Email**
   - User receives password reset email
   - Email contains reset link with token
   - Link format: `whoknowsball://auth/reset-password?token=xxx&type=recovery`

3. **Open App via Deep Link**
   - User taps the reset link in email
   - iOS/Android opens the WhoKnowsBall app
   - Deep link navigates to PasswordResetScreen
   - Supabase automatically handles the token from the URL

4. **Reset Password**
   - User enters new password (min 10 characters)
   - User confirms new password
   - User taps "Reset Password"
   - App calls `supabase.auth.updateUser({ password: newPassword })`
   - Success! User is navigated to LoginScreen

5. **Login with New Password**
   - User logs in with new password
   - Access to app is restored

### Technical Flow

```
ForgotPasswordScreen
  ↓ supabase.auth.resetPasswordForEmail(email, { redirectTo: 'whoknowsball://auth/reset-password' })
  ↓
Supabase sends email with reset link
  ↓
User clicks link: whoknowsball://auth/reset-password?token=xxx&type=recovery
  ↓
Deep link opens app → PasswordResetScreen
  ↓ Supabase auto-handles token from URL
  ↓ User enters new password
  ↓ supabase.auth.updateUser({ password: newPassword })
  ↓
Success → Navigate to LoginScreen
```

## 4. Testing the Password Reset Flow

### Test Checklist

1. ✅ **Request Reset Link**
   - Open app and navigate to Login screen
   - Tap "Forgot Password?"
   - Enter a valid email address
   - Tap "Send Reset Link"
   - Verify success message appears

2. ✅ **Receive Email**
   - Check email inbox for password reset email
   - Verify email contains reset link
   - Verify link uses `whoknowsball://` scheme

3. ✅ **Deep Link Opens App**
   - Tap the reset link in email
   - Verify app opens (not browser)
   - Verify PasswordResetScreen appears

4. ✅ **Reset Password**
   - Enter new password (min 10 characters)
   - Confirm new password
   - Tap "Reset Password"
   - Verify success and navigation to LoginScreen

5. ✅ **Login with New Password**
   - Enter email and new password
   - Tap "Log In"
   - Verify successful login

### Common Test Scenarios

**Test 1: Invalid Email**
- Enter invalid email on ForgotPasswordScreen
- Verify error message: "Please enter a valid email address"

**Test 2: Password Too Short**
- Enter password less than 10 characters
- Verify button is disabled
- Verify helper text: "Min 10 characters"

**Test 3: Passwords Don't Match**
- Enter different passwords in "New Password" and "Confirm Password"
- Verify error message: "Passwords do not match"

**Test 4: Expired Reset Link**
- Wait more than 1 hour after requesting reset
- Tap reset link in email
- Verify appropriate error handling (token expired)

## 5. Security Considerations

1. **Token Expiration**
   - Reset tokens expire after 1 hour by default
   - Users must complete reset within this window
   - Expired tokens cannot be reused

2. **One-Time Use**
   - Reset tokens can only be used once
   - After successful password reset, token is invalidated
   - Old tokens cannot be reused

3. **Email Verification**
   - Only emails registered in the system receive reset links
   - Invalid emails receive generic success message (prevents email enumeration)

4. **Password Requirements**
   - Minimum 10 characters enforced in app
   - Matches registration password requirements
   - Supabase may enforce additional requirements

5. **Deep Link Security**
   - Token is passed securely in URL parameters
   - Supabase validates token on the server side
   - App never stores or exposes the token

## 6. Troubleshooting

### Problem: Email not received

**Possible causes:**
- Email in spam folder
- Invalid email address
- Email rate limiting (check Supabase logs)

**Solutions:**
- Check spam/junk folder
- Verify email address is correct
- Wait a few minutes and try again
- Check Supabase Dashboard > Authentication > Logs

### Problem: Deep link doesn't open app

**Possible causes:**
- App not installed
- URL scheme not configured correctly
- Platform-specific configuration issues

**Solutions:**
- Rebuild the app after configuration changes
- Verify `whoknowsball://` scheme in Info.plist (iOS) and AndroidManifest.xml (Android)
- Test deep link manually: `xcrun simctl openurl booted whoknowsball://auth/reset-password` (iOS simulator)

### Problem: "Invalid or expired token" error

**Possible causes:**
- Reset link is more than 1 hour old
- Token already used
- Token tampered with

**Solutions:**
- Request a new reset link
- Ensure link hasn't been modified
- Check Supabase logs for details

### Problem: Password reset succeeds but can't login

**Possible causes:**
- Account is disabled (email not verified)
- Network error during password update
- Password doesn't meet Supabase requirements

**Solutions:**
- Verify email address first
- Check error message on login screen
- Try password reset again
- Contact support if issue persists
